## 2. 发现并修复的问题

Windows PowerShell 原先通过 `WriteAllLines` 生成环境变量覆盖文件，文件使用 CRLF。Linux 安装器读取每行时没有去掉 CR，导致第二台新增的配置值结尾包含 `\r`。

第一台的环境文件是在 Linux 上创建的，因此没有该问题。这是第一台正常而第二台可能出现目录、URL或脚本参数异常的明确环境差异。

修复包含两层：

1. `deploy-to-vm.ps1` 使用 `WriteAllText` 并明确用 LF 拼接行。
2. `deploy/install-agent.sh` 合并覆盖项时再次移除行尾 CR。

修复后验证：`AGENT_NAME`、`AGENT_PLATFORM_URL` 和 `AGENT_REDIS_CONFIG_DIR` 原始字节均不再包含 `0d`，Bash 读取值也不再包含 `\r`。

## 4. Sentinel 结论

第二台单机 Sentinel 的独立检查结果：

```text
PING=PONG
MASTER=127.0.0.1:6379
flags=master
slaves=0
```

因此当前只能证明 Sentinel 进程和本机监控逻辑正常，不能证明三台 Sentinel 的法定票数、互相发现和完整主从拓扑正常。完整拓扑必须在另外两台新服务器准备好后验证。

Maven 构建成功，但现有测试类没有被 Surefire 识别，构建输出为 `Tests run: 0`。本次结论来自第二台虚拟机上的真实接口和服务运行验证。
